## 2026-10-10

### 不規則的邊緣

- 要一條固定不變的不規則邊（Paper Tear 的撕邊），放一張靜止的 `FastNoise`（`SeetheRate = 0`、`Depth = 4`）接到 `Custom` 的第三張圖，沿著邊的方向取一條線：`getr3b(0.27, 沿邊座標)`。回傳值在 0.5 上下，減 0.5 再乘幅度就是邊的偏移量。換一個 x 位置取樣就是另一條互不相關的曲線，紙芯寬度用的是這個。`Seethe` 的數值當種子，改了就換一個形狀。
- `Custom` 裡有 `w`、`h` 兩個變數是影像的寬高，要算長寬比不必另外傳數值進去。
- 旋轉座標時 y 要先乘 `h/w`，兩個方向才是同一個單位，不然斜向的邊會被壓扁。

### 撕紙要怎麼動才自然

- 第一版 Paper Tear 是一條形狀固定的撕邊橫掃過畫面，使用者覺得不自然：真的撕紙時，撕邊的形狀是留在紙上不動的。改成撕裂線固定在紙上，裂口沿著線從一頭走到另一頭，後面留下一道窄縫，接著兩半不變形地往兩邊滑開。
- Paper Tear 第二版「兩半不變形地往兩邊滑開」使用者覺得硬、不好看（2026-10-11）。原因：純平移、兩半完全對稱同步、用 smoothstep、陰影不變。改法：每一半各一個 `Custom` 切出來（帶透明度），再各接一個 `Transform` 做剛體運動，以裂口終點那一頭為 `Pivot` 各轉十幾度、位移用越走越快的曲線（`t*t*(2-t)`）、第二半晚一點出發、順著線往裂口起點方向帶一點漂移；兩半合起來的透明度模糊後當陰影，模糊量和偏移隨離開的程度變大。裂開的階段紙還連著，不能用剛體旋轉（裂口前方會對不上），用取樣位移做成楔形裂口（寬度和「裂口已經走過多遠」成正比），裂完時剛好接上旋轉。要「東西離開畫面」的動作都可以照這個配方：轉一點、加速、錯開時間、陰影跟著變。
- 兩個帶抗鋸齒邊的半張圖沿同一條線拼回去，接縫會透出一條細線（兩邊各 0.5 的透明度疊起來只有 0.75）。還沒分開的地方讓下層那一半整片鋪滿、不切邊。
- `Transform` 的 `Pivot`、`Center` 是 0 到 1 的畫面座標，從「以畫面寬為單位」的向量換算時 y 要乘寬高比。控制節點的運算式裡用 `comp:GetPrefs('Comp.FrameFormat.Width')/comp:GetPrefs('Comp.FrameFormat.Height')` 取得。`Transform` 的 `Angle` 正值是逆時針。
- 建置腳本第一個 `AddTool` 就回傳 nil：Resolve 不在 Fusion 頁面，`GetCurrentComp()` 拿到的是別的合成，使用者在 Edit 頁面測過東西之後常這樣。`lib.lua` 的 `L.comp` 現在會先檢查頁面並印 `NOT_ON_FUSION_PAGE`，跑 `lab.lua` 就會回到實驗片段（它會移播放頭，不靠播放頭剛好停在哪）。`CreateEmptyTimeline` 在 Fusion 頁面會失敗，要先切到 Edit 頁面。空的 Fusion 合成（`InsertFusionCompositionIntoTimeline`）長度是 5 秒、時間單位是時間軸的影格（24fps 是 0 到 119），和現在那支 48fps 影片的 0 到 235 不同，測試指令的取樣畫格要跟著改。
- 試過讓兩半位移量隨「裂口經過多久」線性增加（楔形張開），結果是剪切變形，畫面裡的圓會被拉成橢圓，不能用。位移只能有很小一段是漸變的（裂口尖端），其餘要整塊一起動。
- 被移開的那一半取樣原圖時座標會超出 0 到 1，要自己判斷並改顯示後一段，不然是黑的。
- `Custom` 的中間變數是照編號依序算的，`i1` 的式子裡用到 `i2` 會整張變黑，沒有錯誤訊息。
- 這一版每個像素的式子很長，1080p 一格約 0.6 秒，Edit 頁面不會即時播放。

### 在指定時間點觸發的動作

- Punch Zoom 的做法：一個運算式把時間點清單解析出來，對每個已經過去的時間點算一個脈衝（幾格內升到 1，再用 `(1-u)^3` 落回 0），取最大值，用 `Point(脈衝, 縮放量)` 一次帶出兩個數。所有效果（RGB 分離、模糊、震動、閃白）都乘上這個脈衝，沒打的時候全部是 0，畫面和原片完全相同。
- 照 BPM 打不必把每一拍都列出來，算出目前是第幾拍，只看最近三拍就夠。
- RGB 分離不用拆三個通道再合：在 `Custom` 裡紅、綠、藍各用略有不同的縮放倍率取樣同一張圖。三個倍率都要大於等於基本倍率，不然邊緣會取到畫面外變黑。
- 震動的位移會讓邊緣露出黑邊，基本倍率要同時加上兩倍的震動幅度來蓋掉。
- `DirectionalBlur` 的 `Type` 設成 `Zoom` 就是放射狀模糊，`Length` 0.02 已經很明顯，0.04 字就看不清楚了。
- 每格不同的亂數在運算式裡用 `math.sin(time*12.9898 + 種子)*43758.5453` 取小數部分。

### 節點名稱

- 節點不要取名 `Name1`、`Name2`。Bar Chart 一開始把名稱文字取名 `Name1` 到 `Name8`，其他節點的運算式寫 `Name1.Font` 去引用它，結果那些節點算不出畫面、也沒有錯誤訊息；同樣寫法引用 `Number1` 就正常。改名 `RowName1` 之後就好了。原因沒有查，推測 `Name` 開頭和節點自己的 `Name` 屬性衝突。
- 一長串節點算不出畫面時，寫一支小腳本從上游往下游逐個節點算圖，看第一個失敗的是誰。算圖的檔名前綴一樣不能以數字結尾，不然每個都會被誤判成失敗。

### 一個 Custom 畫多個長條

- Bar Chart 的八條長條是同一個 `Custom` 畫的：先算像素落在第幾列（`floor((頂端 - y)/列高)`），再用一串巢狀 `if` 依列號選出那一列的長度（八個 `NumberIn` 各放一條）。比八組遮罩加八個 `Merge` 省很多節點。
- 名稱和數字每列各一個 `Text+`，第二列以後的字型、顏色用運算式連到第一列，巨集只要開出第一列的字型和顏色。

### 讓使用者用關鍵幀控制「現在第幾句」

- 運算式可以讀任何輸入在其他時間點的值：`節點:GetValue("輸入ID", 時間)`，放在迴圈裡也行，節點讀自己的輸入也行。`輸入[time-5]`、`self:GetInput(...)`、`輸入:GetConnectedOutput()` 這幾種寫法在運算式裡都得不到值，也沒有錯誤訊息。
- 用這個做出「第幾句」滑桿（`L.cur`）：取 `floor(值 + 0.0001)` 當行號，往回一格一格讀到數值不同為止，就知道這一句是幾格前開始的，進場動畫從那裡算；往後讀可以知道幾格後換句，用來淡出。往回最多看 90 格、往後 60 格，夠動畫用又不會拖慢。
- 滑桿不能設成整數（`INP_Integer`）。整數滑桿在兩個關鍵幀之間會四捨五入，變成在兩個關鍵幀的正中間換句。用一般滑桿加 `floor`，數值要到後面那個關鍵幀才剛好變成下一個整數，換句點就落在關鍵幀上。代價是數字要一次加 1，跳號或往回調會閃過中間的句子。
- `AddModifier("輸入", "BezierSpline")` 會在目前的時間點自動多打一個關鍵幀，測試時要把不是自己設的刪掉（`L.keys` 會處理）。
- 包成巨集之後，把關鍵幀打在巨集開出來的那個輸入上（腳本裡 `macro:AddModifier("Input2", "BezierSpline")`），裡面的運算式一樣讀得到。Edit 頁面 Inspector 的關鍵幀應該走同一條路，但還沒有實測。
- 清單該照時間還是照關鍵幀，用一個勾選框讓使用者明講。不要從內容猜：`100 分` 這種以數字開頭的字卡會被當成第 100 秒。

### 量文字寬度、拼接不同大小的文字

- 運算式可以讀到一個節點算出來的影像範圍：`節點.Output.DataWindow` 有 `left`、`right`、`top`、`bottom`（像素），`節點.Output.Width`、`.Height` 是畫布大小。`Text+` 的範圍就是字的實際外框，所以能量出文字寬度。文字是空的時候不要讀，先判斷 `StyledText.Value == ""`。
- 節點不能在自己的運算式裡讀自己的 `Output`（例如 `Size` 用到 `自己.Output.Height`），會整個算不出畫面、沒有錯誤訊息。畫布大小改用 `comp:GetPrefs("Comp.FrameFormat.Width")`。同理，位置不能依賴自己的寬度：Variety Caption 的三段文字都固定放在畫面中央，量完寬度後由 `Merge` 的 `Center` 擺到定位。
- Variety Caption 一句裡的強調詞是這樣做的：把一行切成「前、強調詞、後」三個 `Text+`，各自量寬度後排成一列。`Text+` 不同大小的字是垂直置中對齊的，強調詞放大後要往上移 `0.28 × Size × (倍率 − 1) × 寬高比`，底部才會和其他字對齊。
- `Text+` 的字高大約是 `Size × 畫布寬 × 0.557` 像素（微軟正黑體粗體、Arial Bold 都接近）。

### 厚描邊

- 多層厚描邊不要用 `Text+` 自己的描邊，用 `ErodeDilate`（`Filter = 3` 是圓形，`XAmount` 是畫面寬度的比例，0.006 在 1080p 約 11 像素）把文字的 alpha 長大，每一層長得更多一點，再用一個 `Custom` 由內往外疊色。好處是不同節點拼起來的字和手繪形狀可以共用一圈描邊，轉角是圓的。`L.inked` 包好了兩層的版本。
- 某一層粗細是 0 時要把那一層關掉，不然它和裡面那層一樣大，會把裡面那層的顏色蓋掉。
- 漸層的端點顏色要能用運算式換（配色預設組），就不能用 `Background` 的漸層（顏色停駐點不是數值輸入）。改用 `Custom`：`n1`–`n3` 上方顏色、`n4`–`n6` 下方顏色，依 `y` 內插，乘上文字的 alpha。
- 配色預設組：下拉選單（`ComboControl`，值從 0 起算）加一個寫在運算式裡的表 `({{...},{...}})[選項][第幾個數]`，第 0 項是自訂，改讀幾個 16×16 的 `Background` 的顏色，那些顏色用 `ControlGroup` 開到巨集上。

### 用 Custom 畫形狀

- 線條和形狀的邊緣要柔一個像素：`min(max((半寬 − 距離) × 像素數 + 0.5, 0), 1)`，「像素數」是把距離換成像素的倍率（距離以畫面高為單位時就是 `h`）。直接用 `<` 比較會有鋸齒。
- 彎曲的箭頭：把像素投影到起點到終點的直線上，得到沿線位置 `t` 和偏離距離 `s`，線條就是 `|s − 長度 × 彎度 × sin(180t)| < 半寬`。畫線動畫只要限制 `t <= 進度`。箭頭尖端兩撇的方向在控制節點的運算式裡先算好（終點的切線方向各轉 28 度），用 `PointIn` 傳進去。
- 怒氣記號是四段圓弧：座標取絕對值摺到同一個象限，畫一個圓心在對角線外側 `(1, 1)`、半徑 0.8 的圓環，只留 `|x| < 0.9` 且 `|y| < 0.9` 的部分。圓心太近、半徑太小時四段會黏成一團。
- 集中線：角度除以 360 乘上條數得到第幾條，用條號算亂數決定這一條從多遠開始、要不要畫；寬度隨著離中心的距離變寬就會是尖的。亂數的種子用 `floor(time / 幾格)`，線條就會每隔幾格換一組。`Custom` 的 `sin` 是度，亂數要用大一點的乘數（`sin(條號 × 744.3 + 種子 × 91.7) × 43758.5453` 取小數）。

### 尚未驗證（綜藝字幕這一批）

- Variety Caption、Side Note、Text Label、Reaction Mark 和改過的 Kinetic Lines 都只在 Fusion 頁面的實驗合成裡驗證：巨集貼得回來、控制項齊全、算圖正確。還沒從 Edit 頁面拖過，也還沒在 Edit 頁面的 Inspector 上實際打過 `Line Number` 的關鍵幀。
- 下拉選單（`Colours`、`Entrance`、`Mark`、`Frame`、`Position Is The`）在 Edit 頁面 Inspector 顯示成什麼樣子沒看過。
- Variety Caption 的 `Custom` 配色（七個自訂顏色）、`Sway`、Reaction Mark 的 `Use My Colours`、Side Note 的負彎度和關掉箭頭、Text Label 的自訂配色、半透明底色、`From Below`／`From Above`／`Pop` 以外組合的離場，沒有個別算圖看過。

### 同一個合成裡放兩份範本

- 節點名稱不能和控制節點上的控制項 ID 相同。原本輸出節點叫 `LblOut`，控制項也有一個 `LblOut`。貼第二份時 Fusion 把節點改名成 `LblOut_1`，同時把運算式裡所有 `LblOut` 字樣都改掉，連指控制項的那些也改了，第二份的運算式就全部算不出值，畫面是空的、沒有錯誤訊息。只貼一份時看不出來。輸出節點一律取名 `…Final`。Chapter Bar、Number Counter、Bar Chart 等較早的範本還沒檢查有沒有同樣的撞名。
- 貼上時 Fusion 會把運算式裡的節點名稱（包括寫在匿名函式裡的）一起改成新名字，所以巨集可以在同一個合成裡貼很多份。`scripts/compose.lua` 就是做這件事：貼一份、記下新出現的 `MacroOperator`、用 `GetInputList()` 依 `INPS_Name` 找到輸入 ID 來設定，再貼下一份，最後用 `Merge` 疊起來。Text Label 的組合預覽圖就是這樣算的（`FX_TEMPLATE` 指定範本，`FX_SPEC` 指定每一份的設定檔）。

### 用距離函數畫外框

- Text Label 的九種外框是同一個 `Custom` 畫的：算出像素到形狀邊緣的距離 `d`（裡面是負的），底色是 `d < 0`，邊線是 `|d| < 半寬`，陰影是把座標位移後再算一次 `d`。圓角方框的距離是 `sqrt(max(qx,0)² + max(qy,0)²) + min(max(qx,qy),0) − r`，其中 `qx = |u| − 半寬 + r`。`r = 0` 是方框，`r = 半高` 是膠囊。
- 其他形狀是在這個距離上加工：斜切是先把 `u` 減掉 `斜率 × v`；緞帶是和「兩端往內凹的 V 形」取 `max`；對話泡泡是和一個三角形取 `min`；角標是只在兩個對角附近保留邊線。形狀由下拉選單決定哪些參數是 0，不用寫九套運算式。
- 底色、邊線、陰影三張遮罩分別存在同一張圖的紅、綠、藍，下一個 `Custom` 再上色，省掉兩個節點。
- 單行文字的外框高度不要用量出來的字高（「一」和「題」高度差很多），用 `Size × 寬高比 × 0.6` 當最小高度，同樣大小的標籤才會一樣高。

### 連續拉遠的鏡頭感（Comic Intro）

- 原本的 Comic Intro 是「漫畫頁固定大小翻一陣子，然後標題才開始縮小」，看起來像投影片換頁接一個縮放，不像一個鏡頭。改法是讓漫畫頁自己也一路縮小：`頁面倍率 = 起始 × (結束/起始) ^ 進度`，指數式的變化看起來才是等速後退。標題縮得比頁面快很多（60 倍對 5 倍），兩層速度不同就會讀成「頁面在字的後面、離得比較遠」。
- 程序產生的圖案要縮放，不用把它算成大圖再接 `Transform`，直接在 `Custom` 裡把取樣座標換掉：`((x − 軸心x)/倍率 + 軸心x + 8)`。加 8 是因為縮小後座標會變負，`frac` 和 `floor` 遇到負數會出錯。圖案本來就是用 `frac` 平鋪的，所以怎麼縮都鋪得滿。
- Comic Intro 已經改用共用的那一套（`comicintro.lua` 加 `macro.py`、`check.lua`），舊的獨立腳本和純紋理的標題版都刪掉了。`Zoom Pivot` 的預設值（0.5482, 0.4995）是當初用一支小程式對預設文字算出來的「離筆畫邊緣最遠的點」，那支程式沒有留下來，換文字後要手動調。

### 放大很多倍的文字不能直接接模糊、擴張、陰影（會讓 Resolve 當掉）

- Comic Intro 的標題一開始放大 60 倍，`Text+` 算出來的影像範圍是畫面的幾千倍大。直接把它接到 `Blur`、`ErodeDilate`、`Shadow`、`Transform`，這些節點會處理整個範圍，算圖卡住幾分鐘後 Resolve 整個當掉、跳出「問題報告」視窗。當掉前沒有任何錯誤訊息，腳本只是不回傳。
- 做法：先把文字 `Merge` 到一張和畫面一樣大的透明底上，**後面再接一個 `SetDomain`（`Mode = "Set"`）**，之後才接會擴大範圍的節點。只有 `Merge` 不夠，試過，一樣當掉；加了 `SetDomain` 之後整段 30 秒算完。`comicintro.lua` 的 `framed()` 就是這兩個節點。
- 試這類可能很重的改動時，先用 `timeout 150` 包住指令、只算幾格（`FX_STEPS` 設大），正常才算整段。
- Resolve 當掉後視窗標題會變成「DaVinci Resolve问题报告」，用 PowerShell 的 `Get-Process Resolve | Select MainWindowTitle` 看得出來。這時所有腳本都連不上。使用者同意的話可以結束行程、重新啟動 `Resolve.exe`，等 45 秒左右會停在專案管理器，再用 `GetProjectManager():LoadProject("testsss")` 開專案、跑 `lab.lua` 回到實驗合成。沒有同意就不要自己重啟。
- 一長串節點的效果看不出來時，先個別算中間節點（`comicintro.lua` 有 `FX_DEBUG=節點名稱`）。這次中間節點都對，最後是控制項的問題：在 `Background` 上加了一個叫 `Depth` 的控制項，和它原有的位元深度輸入撞名，讀到的值是 0，所有乘上它的效果都消失。這和之前 `Offset` 撞名是同一個坑，自訂控制項的 ID 一律加前綴。

### 讓平面的字看起來有厚度

- 字是從一塊板子挖出來的洞，洞後面是另一層畫面。兩樣東西就夠讓它有厚度：一是板子落在後面那層的陰影（把字的 alpha 往右下移、模糊，後面那層在「移走之後沒蓋到」的地方變暗，也就是洞的左上內緣）；二是洞口一圈亮線（字的 alpha 擴張後減掉原本的，疊在板子上）。位移、模糊、擴張的量都要乘上目前的縮放倍率，並設上限，不然放大時會過頭。
- 兩層顏色不搭時，把後面那層染成板子的顏色（亮度乘上板子顏色，再加一點亮度平方把亮部推回白色），看起來就像同一個東西的一部分。

### 開場特效和正片怎麼對齊（Photo Stack）

- 使用者的抱怨是「開場動畫佔掉正片開頭的時間」。繞了三版才弄清楚真正要的是：其他照片疊上來的那段時間不算正片，最後一張照片飛進來的那一刻正片才開始，而且之後要無縫接下去。
- 「無縫接下去」只有一種做法：最後那張照片播的就是片段當下的畫面（`SourceTime = time`）。任何停格、倒帶、位移都會讓這一段結尾的畫格和下一段開頭對不上，除非使用者另外複製片段來配合。
- 那張照片在飛進來之前本來就不在畫面上，所以它出現前的時間只會被模糊的背景用掉。問題其實只剩「使用者不知道它什麼時候出現」：原本是 `(Stack Complete At − Slide Time − 0.01) × 片段長度`，沒人算得出來。改成一個以秒計的控制項（`Last Photo Arrives After`，預設 2），其他照片的間隔和開始放大的時間都從它推出來。使用者只要記得「從想開始的那一格往前 2 秒切」。
- 一般化：動畫裡有一個「使用者要拿來對齊素材的時間點」時，把那個時間點做成以秒計的獨立控制項，其他時間從它推導。不要讓它是好幾個比例參數算出來的結果。
- 倒帶（`RenderStart + 已播的格數 × (1 − 放大進度)`）和停在第一格留著當備案，給正片前面沒有多餘畫面的情況：把正片複製一份放前面、剪成開場的長度再套。這種做法那一小段的聲音會和正片重複，要提醒使用者靜音。
- 不要做成「套在整段正片上，畫面自動往後推幾秒」。Fusion 特效只管畫面，聲音不會跟著延後；而且動畫結束後整段正片的每一格都還要經過特效的節點，會拖慢播放。

### 一次做 13 個範本學到的

- **`Custom` 的中間變數照編號依序計算**。`Intermediate5` 裡用到 `i8`，整個節點算出全黑、沒有錯誤訊息。後面的式子只能用編號比自己小的中間變數。
- **`Custom` 取樣很小的圖會混到隔壁的像素**。把五個顏色放進 5×1 的圖，用 `getr3b((k + 0.5)/5, 0.5)` 取，拿到的是相鄰兩色的平均。每個顏色給 10 像素寬（50×4 的圖）就正確。
- **控制節點自己的運算式裡，不帶節點名稱的 `Gap` 讀不到同名的自訂控制項**：`Point(Gap.X, 0.5)` 回傳 0.5，和別的值相加則整個變成 nil，下游全部算不出來、沒有錯誤訊息。寫成 `HidCtrl.Gap.X` 就正常。`WA`、`Hit` 這些名稱不帶節點名稱也能用，所以是 `Gap` 這個名字撞到了別的東西。自己的運算式裡引用自訂控制項，一律帶節點名稱最保險。
- 找「哪個節點算不出來」：`L.ship` 支援 `FX_DEBUG=節點名稱`，一個個算，看哪一個開始沒有畫格；再用 `tool:GetInput(id, frame)` 逐一印控制節點的驅動值，回傳 nil 的那個就是壞掉的運算式。把運算式拆成小段用 `SetExpression` 逐段試，幾分鐘就能定位。
- **轉場的畫面外用鏡像補滿**：甩鏡和推近都會取到畫面外。`abs(frac((u + 3)/2)*2 - 1)`（`L.mirror`）把座標摺回 0 到 1，畫面外是鏡像重複的畫面，快速移動時看不出來，比黑邊好。
- **連續推近的轉場**：兩段用同一條指數曲線，A 的倍率是 `Z^S`、B 是 `Z^(S − 1)`（S 從 0 到 1），中間交叉淡化。這樣速度感是連續的，不會在換段時頓一下。
- **故障畫面的做法**：每條橫帶用 `frac(sin(帶號*12.9898 + 時間步*78.233)*43758.5453)` 取亂數，決定要不要橫移、移多少；另一組更細的橫帶再疊一次小位移；用方塊的亂數挑一些方塊改讀別處的畫面；紅藍兩色的取樣位置各往一邊偏。轉場版再用橫帶的亂數和進度比較，決定這一帶顯示前一段還是後一段。
- **`L.inked` 可以做兩色填色的字**：同一個文字遮罩上兩次色（兩組顏色），第二份用 `RectangleMask` 從文字左緣往右長。文字的左緣和寬度用 `Output.DataWindow` 量。
- **多行貼上的 bash 指令裡如果有很長的 heredoc 內含單引號，有時整個指令會解析失敗**（`unexpected EOF while looking for matching`）。Lua 腳本改用寫檔工具直接寫，不要塞在 heredoc 裡。
- 停格、倒數這類「照真實秒數」的東西，秒數一律用 `(time − RenderStart) / 影格率` 算，影格率用 `comp:GetPrefs("Comp.FrameFormat.Rate")`，並留一個 `FpsOverride` 控制項給使用者修正。

### 改範本名稱、和內建範本比較

- 改名時 `install.bat` 不會刪掉範本資料夾裡舊檔名的那一份，要自己刪，不然特效庫裡新舊兩個都在。要改的地方：`templates/` 的檔名、建置腳本裡 `L.ship` 的 `name`、`docs/templates/` 的檔名和內文、`previews/` 的 GIF、`previews.sh`、README、SKILL.md 的表格。
- 內建範本包在 `C:\Program Files\Blackmagic Design\DaVinci Resolve\Fusion\Templates\Templates.drfx`，它是 zip 檔，`unzip -l` 可以列出全部名稱（Resolve 21.1.1 有 417 個）。取名前先比對，避免和內建的同名或只差一個字母。
- 內建範本解壓到暫存資料夾後，可以直接用 `check.lua` 貼進實驗合成算圖，和我們的做並排比較。內建的 `Glitch` 轉場不是包成單一群組，`check.lua` 讀不了；其他試過的都可以。

### 腳本不寫死路徑

- 在 `fuscript` 裡，`debug.getinfo(1, "S").source` 是 `@` 加上執行時給的路徑，原樣不變：給相對路徑就是相對的。要絕對路徑得自己接上目前資料夾（Windows 用 `io.popen("cd")` 讀）。`Saver` 的輸出路徑必須是絕對的。
- Lua 字串裡比對路徑分隔符號的樣式要寫 `[/\\]`（兩個反斜線）。透過殼層的 heredoc 餵給 Python 再寫進 Lua 檔時，反斜線會被吃掉一半，變成一個，Lua 報 `invalid escape sequence`。需要反斜線時在 Python 裡用 `chr(92)` 組出來，改完一定要實際跑一支。
- 跟機器有關的設定（專案名稱、素材檔名）放在不進 git 的 `scripts/local.lua`，repo 裡只留範例檔。素材檔名也算私人資訊，不要寫進腳本的預設值。

### 標記和說明類的九個範本

- 要「某個值在過去某一格是多少」：在另一個節點的運算式裡寫 `控制節點:GetValue("輸入ID", 影格)`。座標型的輸入回傳的表用 `v.X or v[1]`、`v.Y or v[2]` 讀。對關鍵幀有效（Click Ripple 用它讓波紋留在點下去那一刻的位置）；如果那個輸入本身是用含 `time` 的運算式驅動的，拿到的會是現在的值，測試時要用真的關鍵幀：`tool:AddModifier("輸入ID", "PolyPath")` 之後 `tool.輸入ID[影格] = {x, y, 0}`。
- `Text+` 的文字顏色可以連到別的節點：對 `Red1`、`Green1`、`Blue1` 設運算式。`HorizontalLeftCenterRight` 也能設運算式，用來做「文字在左邊或右邊」的選項。`AngleZ` 正值是逆時針，和 `Custom` 裡自己算的角度方向一致。
- `compose.lua` 加了 `FX_INPUTS=1`：每一份特效各接一個測試畫面，疊在黑底上，用來做 Split Screen 這種「好幾個片段各套一次」的預覽。
- `L.ship` 加了 `FX_PT="Id=0.3:0.4"` 設座標型控制項。
- 大小類的參數統一以畫面高度為 1（寬和高都是），這樣寬高填一樣就是正圓、正方形。以畫面寬度為 1 的話，使用者要自己乘 16:9。
- 動畫時間用秒的寫法：`(time - comp.RenderStart + 1)/(秒數*FPS)`，`FPS` 是 `iif(FpsOverride > 0, FpsOverride, comp:GetPrefs('Comp.FrameFormat.Rate') or 24)`。標記類用秒比用整段比例合理：標題拉長時，畫出來的速度不該變慢。
- 長度貼合文字的底條（Step Badge 的膠囊）：在 `Custom` 的 `NumberIn` 運算式裡讀 `文字節點.Output.DataWindow`，`(right - left)/Output.Width` 是文字佔畫面寬度的比例。底條用「到線段的距離小於半徑」畫，兩端自然是圓的；注意圓頭會比線段多出一個半徑，長度要先扣掉。讓文字只在底條已經伸到的地方出現：把文字的 alpha 乘上底條的 alpha。
- 在 `Custom` 裡轉動畫面：取樣座標先乘 `w/h` 換成正方形的單位再轉，轉完除回去，不然畫面會被拉歪。轉了之後四個角會取到畫面外：把放大倍率再乘上 `cos(角度) + 寬高比*sin(角度)` 就剛好蓋滿（這個倍率在控制節點的 Lua 運算式裡算，那邊的三角函數是弧度），取樣用 `get?1d`（延伸邊緣）保險。

### Video Wall 重做：圓角、邊框、陰影

- **有圓角的格子牆**：第一個 `Custom`（float32）替每個像素算出「格子內的位置、第幾格、到格子邊緣的距離」存進 R、G、B、A。距離用圓角矩形的公式：`sqrt(max(qx,0)^2 + max(qy,0)^2) + min(max(qx,qy),0) - 半徑`，`q` 是「離格子中心的距離 − 半邊長 + 半徑」，y 方向要乘 `h/w` 換成和 x 一樣的單位。後面的節點只看這個距離：小於 0 是螢幕、0 到邊框寬是邊框、其餘是牆。邊緣用 `clamp(0.5 - 距離/一個像素的大小)` 當覆蓋率來混色，傾斜或圓角才不會有鋸齒。
- **陰影不用另外算形狀**：在偏移一點的位置再讀一次同一張距離圖（`geta1d(x - dx, y + dy)`），距離小的地方就是有東西擋住光，除以一個柔邊寬度就是陰影濃度。
- `Custom` 只有三張輸入圖。需要「座標圖 + 兩個片段 + 圖集」四張時拆成兩個：前一個只畫兩個片段那兩格（alpha 標記畫了沒），後一個補其他的。
- 轉場的頭尾要和原片段一模一樣：圓角、傾斜這類會動到主畫面邊緣的東西，乘上一個在頭尾各 12% 內從 0 升到 1 的係數。邊框和陰影畫在螢幕外面，頭尾時鏡頭剛好只看到螢幕，所以不用處理。
- 縮放照「倍率」等速（`起點 * (終點/起點)^t`）比照大小等速自然，Comic Intro 和 Video Wall 都這樣做。

### 計次、條列、手機外框、Sticker Pop

- **做新範本前先比對現有的和內建的**。這次八個構想裡只有一個需要新做，三個是現有範本加一個模式（Number Counter 計次、Kinetic Lines 條列、Sub Window 手機外框），其餘 Resolve 內建或現有範本已經能做（`Blanking Fill` 補滿直式畫面、`Text+` 的字卡、Variety Caption 的 `Slam`）。使用者明講過這些範本還在快速迭代，改的時候不用為了舊專案保留舊的參數名稱或預設值，怎樣好就怎樣改。
- **同一份清單「目前這行亮、其他行暗」**：兩個 `Text+` 放同樣行數的文字，一個只留目前這行、一個只留已經出現過的行，其餘行都用佔位字元，兩個疊起來每一行的位置就會一致。這時不能改字的大小（行距會跟著變），進場只能用位移和淡入。
- **帶透明度的圖要保留透明度**：用 `Transform` 移動縮放（它會保留 alpha），外框用 `ErodeDilate` 把 alpha 往外長、在 `Custom` 裡墊到圖的後面（`r1 + (1 - a1)*a2*顏色`），陰影是同一張圖模糊後錯開位置再讀 alpha。Sub Window 那種「把片段裁進形狀」的寫法會無視來源的 alpha。
- **套在片段上的特效只能畫在片段自己的畫框裡**（推測，還沒有專門驗證）。所以 Sticker Pop 不做位置控制項，位置交給片段自己的 `Transform`，圖預設縮到 0.7 留空間給彈過頭和陰影。
- **Sub Window 的外框樣式**：拆成兩個 `Custom`。前一個只把片段裁進「畫面區域」（alpha 是覆蓋率），後一個畫外框。外框和畫面區域是兩個各自的圓角矩形，四邊的寬度（左右、上、下）由控制節點算好傳進來，所以拍立得的寬下緣、視窗的標題列只是不同的邊寬。樣式各自的裝飾分兩類，各佔一個中間變數：「蓋上去的」（視窗的三個圓點、手機的鏡頭孔、膠帶）和「挖掉的」（底片的齒孔、雙線中間的空隙），都寫成距離再共用同一段抗鋸齒。
- **小窗放大成全畫面**：用一個 0 到 1 的值把位置、大小、寬高比、圓角、邊寬、傾斜、放大倍率全部內插到「佔滿畫面」的狀態，等於 1 的那一格直接輸出原圖。片段的寬高比在控制節點裡用 `SrcA.Output.Width / SrcA.Output.Height` 取得。
- **跟著外框轉的文字**：`Text+` 的 `Center` 用運算式把「外框座標系裡的位置」轉回畫面座標（x 方向要除以寬高比），`AngleZ` 設成同一個角度。`Text+` 的字高大約是 `Size` 乘畫面寬度的 0.47 倍。
- 使用者在 Edit 頁面挑了幾個範本從特效庫拖進去，都能載入、畫面大致正常（2026-10-11）。這只確認了「巨集範本拖得進去」，各範本的細節和下面幾節列的未測項目仍然沒有逐一驗證。
- Preferences > System > General 的 `Automatic scripted actions`：決定內嵌在專案或範本裡的腳本動作可以自動執行到什麼程度，「只允許安全的子集」或「全部允許」，官方建議留在 `Allow safe`。和 `External scripting using`（外部腳本能不能連進來，我們用 `Local`）是兩回事。我們的範本裡的運算式算不算在內、在 `Allow safe` 下是否全部正常，沒有驗證過。
- **21.1 內建的 MCP 伺服器我們用不到**（2026-10-11 查過，使用者決定不採用）。它在安裝資料夾的 `DaVinciResolve.mcpb`，用 `File > Setup AI Assistants` 設定，只有 14 個工具，核心是 `run_script`：跑 Python 呼叫和 `fuscript` 同一套腳本 API，其餘是查 API 文件、產生 LUT 和 DCTL。沒有比 `fuscript` 多的能力，換過去還要把所有 Lua 建置腳本改寫成 Python。沒有實際接上去用過。

### 對話與社群類：Typing、Comment Card、Chat Bubbles、Subscribe Reminder（2026-10-11）

- **量文字有多大**：運算式裡讀 `某Text.Output.DataWindow`（`left`、`right`、`bottom`、`top`，單位是像素，除以 `Output.Width`、`Output.Height` 變成比例）。沒有接到輸出的 Text+ 也讀得到，所以可以放幾個只拿來量的「尺」。還沒算過圖時四個值是 -1000000 而不是 nil，兩種都要擋。量到的是墨水的範圍：結尾的空白不算、不同的字高度不同。要穩定的行高，量一個只有 `|` 的尺；要算進結尾空白的寬度，量「文字加一個 `|`」再減掉 `|` 的右緣。
- **排版的做法**：文字一律在畫面正中央算出來、量好，再用 `Transform` 搬到要的位置（`Center = 0.5 + 目標左上角 - 量到的左上角`）。卡片的寬高由量到的尺寸加總，Comment Card 整張都是這樣排的。
- **不要讓很多運算式都去讀 `DataWindow`**。Chat Bubbles 第一版七則訊息各自量寬度，位置又一則疊一則地互相引用，每格要 4 秒。改成每則訊息一個 Text+ 自己畫泡泡（見下一則），只留三個內容固定的尺（一行的高度、兩行的高度、三個點的寬度），每格 0.6 秒。
- **一個 Text+ 同時畫字和自動貼合的底框**：`Enabled2 = 1` 打開第二層，`ElementShape2 = 2`、`Level2 = 0`，用 `ExtendHorizontal2`、`ExtendVertical2`、`Round2` 調留白和圓角，`Red2` 等設顏色。預設的層次就是底框在字後面。**第二層的輸入要在 `Enabled2` 設成 1 之後過一下才會出現**，馬上去設會是 nil：設完用 `while t.ExtendHorizontal2 == nil do bmd.wait(0.05) end` 等它（要先 `comp:Unlock()`）。靠左靠右可以用運算式切：`HorizontalLeftCenterRight` 設 `iif(右邊, 1, -1)`，泡泡就會從 `Center` 往另一邊長，不用知道寬度。
- `EllipseMask` 的 `Height` 是以畫面「寬」為單位，`RectangleMask` 的 `Height` 是以畫面「高」為單位。要畫正圓：橢圓的寬高填同一個數；要畫正方形：矩形的高要乘寬高比。`RectangleMask` 的 `CornerRadius` 設 1 再給正方形的寬高就是圓。遮罩可以一個接一個（後一個的 `EffectMask` 接前一個的 `Mask`）疊成愛心、鈴鐺這種圖形；`EllipseMask` 的 `Solid = 0` 加 `BorderWidth` 是空心圓環。
- 自訂控制項叫 `Start` 會撞到 `Background` 漸層的 `Start`（讀回來是一個座標），算圖直接失敗、沒有錯誤訊息。又一個撞名的例子，驅動值一律加前綴。
- 控制項的顯示名稱裡不要有等號。`compose.lua` 的設定檔用第一個等號切開名稱和值，`Characters Per Second (0 = fit…)` 會被切錯，印出 `no control`。用冒號（`0: fit…`）。
- **建置腳本中途出錯會把合成留在鎖定狀態**，而且每失敗一次多鎖一層。之後的腳本看起來正常但行為怪異。除錯時用 `xpcall(function() dofile("build/x.lua") end, debug.traceback)` 包起來看是哪一行，結束後 `while comp:GetAttrs().COMPB_Locked do comp:Unlock() end`。`fuscript` 對腳本錯誤常常什麼都不印就結束，「沒有 render 那一行」就是出錯了。
- 內容同時有單引號、三引號和反斜線的檔案不要用殼層 heredoc 寫（殼層會說找不到對應的引號），用 Write 工具寫成檔案再用小腳本拼接。
- 清單裡一則訊息要換行：使用者寫字面上的 `\n`，運算式裡用 `gsub(string.char(92) .. "n", string.char(10))` 換成真的換行，不在運算式字串裡寫反斜線。
- 這四個範本都只在實驗合成裡用腳本測過，沒有從 Edit 頁面拖過。
- **線條圖示和實心圖示用同一組遮罩**：遮罩拼出的形狀接 `ErodeDilate`（`XAmount` 負值是往內縮），再用 `Custom` 算「原形狀減掉縮小的自己」就是外框線，切換成原形狀就是實心。Subscribe Reminder 的拇指和鈴鐺按下前後就是這樣切的。倒讚是同一組遮罩把 y 和角度都乘 -1。
- Subscribe Reminder 第一版是自己想的通用樣式（紅膠囊、鈴鐺另一顆圓鈕），使用者要的是觀眾一眼認得的影片網站排法，而且台灣的口號是「按讚、訂閱、開啟小鈴鐺」三個動作。做這種「大家都看過」的介面，先開瀏覽器看實物再畫（版面照著排、圖示自己拼、不放商標），不要憑印象做通用版。

### 用 .drfx 發佈（2026-10-11）

- `.drfx` 是改了副檔名的 zip，裡面照 `Edit/Titles/x.setting`、`Edit/Effects/…`、`Edit/Transitions/…` 放範本。使用者對它點兩下、按 Install，Resolve 就把這個檔原封不動複製到範本資料夾的最上層（`…\Fusion\Templates\名稱.drfx`），直接讀裡面的範本。使用者實測（Windows、21.1.1 Studio）：先刪掉舊的並重啟確認範本不見，再點兩下安裝，**不用重啟就能用**。我們自己把檔案複製到那個位置也有同樣效果，但那樣要重啟。
- 驗證範本有沒有裝起來不用看畫面：在暫時的時間軸上 `timeline:InsertFusionTitleIntoTimeline("範本名稱")`，裝了會回傳片段，沒裝回傳 nil。只對標題有效，特效和轉場沒有對應的 API。測完用 `mediaPool:DeleteTimelines({tl})` 刪掉自己建的時間軸。
- **分工（使用者 2026-10-11 決定）：我們開發的電腦只用 `install.bat`，`.drfx` 是給下載的人用的。** 不要在開發的電腦上裝 `.drfx`，兩種同時存在時同名範本各有兩份。要測 `.drfx` 本身時先 `install.bat remove`，測完把範本資料夾最上層的 `.drfx` 刪掉、再 `install.bat install` 裝回來。
- `scripts/drfx.py` 打包，`.github/workflows/release.yml` 在 `templates/` 有變動推上 `main` 時自動重建名為 `latest` 的 Release，下載連結固定。Release 的檔名不要有空白（GitHub 會把空白換成點）。
- 往 `.gitignore` 用 `echo >>` 加一行之前先確認檔尾有換行，不然會和最後一行黏在一起（`tmp/dist/`），原本那條規則就失效了。
